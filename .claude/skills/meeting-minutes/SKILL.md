# 회의록 정리 (Meeting Minutes)

회의 중 오간 대화, 메모, 녹취록처럼 정리되지 않은 텍스트를 받아서, 팀에 공유할 수 있는 정형화된 회의록 `.docx` 파일로 만든다.

## 왜 이런 구조인가

회의록은 나중에 참석하지 않은 사람이 읽거나, 몇 주 뒤 "그때 뭐로 결정했더라?"를 확인할 때 쓰인다. 그래서 두 가지가 특히 중요하다:

1. **안건별 논의 내용과 "결정된 것"이 분리되어 있어야 한다.** 논의 과정은 안건 섹션의 불릿으로, 실제로 누가 언제까지 뭘 하기로 했는지는 별도의 액션 아이템 표로 빼야 나중에 스캔하기 쉽다.
2. **액션 아이템은 담당자와 기한이 없으면 사실상 실행되지 않는다.** 담당자·기한이 빠진 채로 작성하면 회의록의 실질적 가치가 없어지므로, 마지막에 반드시 스스로 점검한다.

## 입력 처리

사용자가 붙여넣는 입력은 형태가 다양할 수 있다 — 타임스탬프가 있는 녹취록, 슬랙 스레드 캡처, 손으로 휘갈긴 메모, 발표자 이름 없이 섞여 있는 대화 등. 완벽하게 구조화된 입력을 기대하지 말고, 다음을 추론해서 채운다:

- **회의 정보(일시/장소/참석자 등)**: 입력에 명시되어 있으면 그대로 쓰고, 없으면 사용자에게 짧게 물어보거나(대화형 세션이면) "미정" 같은 플레이스홀더 대신 빈 값으로 남기지 말고 사용자에게 확인한다. 작성일 등 뻔히 유추 가능한 값(오늘 날짜)은 채워도 되지만, 참석자 명단처럼 추측하면 안 되는 항목은 반드시 확인한다.
- **안건 구분**: 입력에 명확한 안건 구분이 없으면 대화 흐름에서 주제 전환을 찾아 안건으로 나눈다. 각 안건에 발표자가 명시되어 있지 않으면 문맥(누가 그 주제를 주로 이야기했는지)으로 추정하되, 확신이 없으면 빈 칸으로 두지 말고 사용자에게 확인한다.
- **결정 사항 vs 단순 논의**: "~하기로 함", "~승인", "~진행하자" 같은 표현이 결정 사항이다. 액션 아이템은 결정 사항 중에서도 "누가 무엇을 언제까지" 형태로 떨어지는 것만 표로 뺀다. 단순히 논의만 되고 결론이 안 난 항목은 액션 아이템 표에 넣지 말고 해당 안건 섹션의 불릿으로만 남긴다.

## 작업 순서

1. 입력을 다 읽고 안건 단위로 나눈다.
2. 각 안건마다: 제목, 발표자(있으면), 논의 내용 불릿, 결론(있으면 마지막 불릿으로 포함).
3. 전체 결정 사항 중 담당자·기한이 특정되는 것들을 모아 액션 아이템 표로 만든다.
4. 다음 회의 일정이 언급되어 있으면 마지막에 포함한다. 언급이 없으면 이 필드는 생략한다 — 없는 일정을 지어내지 않는다.
5. **자체 검증**: 액션 아이템 표를 다시 훑어서 아래를 확인하고, 그 결과를 체크리스트 항목으로 남긴다:
   - 모든 액션 아이템에 담당자가 지정되어 있는가? **단, "지정되어 있다"는 것은 표에 값이 채워진 것이 아니라, 그 이름/역할이 입력 원문에 실제로 등장하거나 문맥상 특정 1인으로 명확히 좁혀지는 경우만을 뜻한다.**
   - 모든 액션 아이템에 기한이 명시되어 있는가?
   - 회의 정보(일시/장소/작성자/참석자/불참자/안건)에 빈 값이 없는가?
   - 결정 사항 표에 없는 "다음 액션"이 안건 섹션 불릿 속에 묻혀 있지 않은가?

   **담당자 창작 금지(중요)**: 담당자가 불분명한 항목을 "전체 팀원", "해당 팀", "담당자 미정 → 팀 전체 취합" 같은 그럴듯한 대표 표현으로 채워서는 안 된다. 이런 표현은 표에 값이 있어 보이게 만들 뿐, 원문에 없는 정보를 지어낸 것이다 (실제로 이런 실패가 eval에서 발견됨). 원문에 담당자가 명시되지 않았다면 예외 없이 `owner: "미정"`으로 쓰고, 체크리스트에 해당 항목을 ⚠️로 표시한다. 절대 조용히 그럴듯한 값으로 메우지 않는다.

   기한이 누락된 경우도 동일하게 "미정"으로 쓰고 ⚠️ 표시한다. 회의 정보 빈 값은 가능하면 입력에서 유추해 채우거나 사용자에게 물어본다.

## 문서 생성

구조를 다 정리했으면 `scripts/build_docx.py`를 사용해서 `.docx`를 만든다. 이 스크립트가 표 테두리, 헤더 음영, 색상(남색 `#1F3864` 계열) 등 회의록 서식을 전부 처리하므로, 직접 python-docx 코드를 새로 짤 필요가 없다.

1. 아래 스키마대로 JSON 파일을 만든다 (임시 경로에 저장, 예: `/tmp/meeting_data.json`).
2. `python3 <skill_dir>/scripts/build_docx.py <input.json> <output.docx>` 실행. `python-docx`가 없다면 먼저 `pip install python-docx`로 설치한다.
3. 생성된 `.docx` 경로를 사용자에게 안내한다.

### JSON 스키마

```json
{
  "title": "OOO팀 주간 회의록",
  "subtitle": "제 N차 정기 회의 (선택, 없으면 생략 가능)",
  "meta": {
    "일시": "2026년 8월 11일 (화) 10:00 ~ 11:20",
    "장소": "본사 5층 회의실 C",
    "작성자": "김지혜 (Backend)",
    "참석자": "박성한 (팀장), 김지혜 (Backend), ...",
    "불참자": "오재현 (Infra, 휴가)",
    "안건": "① ... ② ..."
  },
  "agenda_items": [
    {
      "heading": "1. 안건 제목",
      "presenter": "발표자 이름",
      "bullets": ["논의 내용 1", "논의 내용 2", "결론: ..."]
    }
  ],
  "action_items": [
    {"task": "할 일", "owner": "담당자", "due": "기한", "status": "예정|진행|완료"}
  ],
  "next_meeting": "2026년 8월 18일 (화) 10:00, 회의실 C",
  "checklist": [
    {"text": "모든 액션 아이템에 담당자가 지정되어 있다", "passed": true},
    {"text": "모든 액션 아이템에 기한이 명시되어 있다", "passed": false}
  ]
}
```

`meta`는 일시/장소/작성자/참석자/불참자/안건 6개 필드를 항상 이 순서로 렌더링한다. 값이 없으면 빈 문자열이 아니라 "없음"처럼 명시적으로 채운다(불참자가 없으면 "없음"). `checklist`의 `passed: false` 항목은 결과물에 ⚠️로 표시되므로, 회의록을 넘기기 전에 사용자가 무엇을 보완해야 하는지 한눈에 보인다.
