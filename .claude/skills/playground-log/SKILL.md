# Playground Log

새 기술/라이브러리를 실험해볼 때마다 "폴더 만들기 → README 쓰기 → 루트 목록에 기록하기"를 매번 손으로 반복하지 않도록 자동화한다.

## 왜 이런 구조인가

이 저장소는 여러 개의 짧은 실험이 쌓이는 곳이라, 나중에 "그때 뭘 테스트했었지?"를 루트 README.md 한 곳에서 훑어볼 수 있어야 값어치가 있다. 그래서 두 가지가 꼭 지켜져야 한다:

1. **폴더명과 표의 기록이 항상 일치해야 한다.** 폴더는 만들었는데 표에 안 남기거나, 표에는 있는데 폴더명이 실제와 다르면 목록의 신뢰도가 깨진다.
2. **폴더명(kebab-case)과 표에 보여줄 주제(사람이 읽는 문구)는 다른 것이다.** 폴더명은 URL/경로에 쓰기 좋은 영문 슬러그여야 하고, 표의 "주제" 칸은 사용자가 실제로 말한 표현(한국어여도 괜찮음)을 그대로 보여주는 게 나중에 스캔하기 더 쉽다.

이 두 가지를 사람이 매번 손으로 맞추면 오탈자나 형식 불일치가 생기기 쉬우므로, 기계적인 부분(폴더/파일 생성, 표 수정, 중복·형식 검증)은 `scripts/create_experiment.py`가 결정적으로 처리한다. 반면 "이 주제를 어떤 영문 슬러그로 부를지"는 의미 판단이 필요한 일이라 스크립트가 아니라 네가 직접 정한다.

## 작업 순서

### 1. 주제와 목적 확보

메시지에 실험 주제(어떤 기술/라이브러리인지)와 목적(뭘 확인해보려는 건지)이 둘 다 없다면, 진행하기 전에 사용자에게 짧게 물어본다. 목적은 1~2문장이면 충분하다 — "그냥 궁금해서" 같은 답도 괜찮으니 억지로 정교하게 만들려 하지 않는다.

### 2. 폴더명(kebab-case slug) 정하기

주제를 영문 kebab-case 슬러그로 바꾼다. 소리 나는 대로 로마자 표기(예: "리액트" → "ri-aek-teu")를 하지 말고, **의미**를 영어로 옮긴다:
- "리액트 서버 컴포넌트" → `react-server-components`
- "장고 인증 시스템 실험" → `django-auth-system`
- 기술/라이브러리의 실제 표기가 있으면 그대로 따른다: "Next.js 15" → `nextjs-15`, "LangChain" → `langchain`
- 소문자, 숫자, 하이픈만 사용하고 나머지 특수문자는 제거하거나 하이픈으로 대체한다.

표의 "주제" 칸에는 이 슬러그가 아니라 사용자가 실제로 쓴 표현(또는 그걸 다듬은 한국어 문구)을 넣는다. 예를 들어 폴더명은 `react-server-components`여도 주제 칸은 "리액트 서버 컴포넌트 실험"처럼 자연스러운 한국어로 남긴다.

### 3. 스크립트 실행

저장소 루트가 어디인지 신경 쓸 필요 없이(스크립트가 `git rev-parse --show-toplevel`로 알아서 찾는다), 아래처럼 실행한다:

```bash
python3 <skill_dir>/scripts/create_experiment.py \
  --slug "react-server-components" \
  --topic "리액트 서버 컴포넌트 실험" \
  --purpose "서버 컴포넌트에서 데이터 페칭이 어떻게 동작하는지 확인한다."
```

`--date`는 생략하면 오늘 날짜(YYYY-MM-DD)가 자동으로 들어간다. 이 스크립트는 다음을 전부 처리한다:

- 저장소 루트에 `<slug>/` 폴더 생성
- 그 안에 `README.md` 생성 (제목 = `--topic`, 본문 = `--purpose`)
- 루트 `README.md`에서 "폴더/주제/날짜" 컬럼을 가진 표를 찾아 새 행 추가
  - 표에 `| - | - | - |` 같은 빈 placeholder 행이 있으면 그 행을 새 데이터로 **대체**
  - 없으면 표의 마지막 행으로 **추가**
- 아래 자체 검증을 수행하고 결과를 체크리스트로 출력:
  - 폴더명이 kebab-case 형식인가
  - 저장소 루트에 동일한 이름의 폴더가 이미 있지는 않은가
  - 루트 README.md에서 실험 목록 표를 찾았는가
  - 표에 동일한 폴더명 행이 이미 있지는 않은가 (중복)
  - 날짜 형식이 YYYY-MM-DD인가
  - 실험 폴더와 README.md가 실제로 생성되었는가

체크리스트에 ⚠️가 있거나 스크립트가 0이 아닌 코드로 종료하면, 원인(대부분 이름 중복이거나 슬러그 형식 문제)을 사용자에게 알리고 어떻게 할지 물어본다 — 임의로 접미사를 붙이거나 다른 폴더를 덮어쓰지 않는다.

### 4. 결과 보고

스크립트 출력(생성된 경로, 표에 반영된 방식, 체크리스트)을 사용자에게 그대로 요약해서 보여준다.
